# Generate an implementation spec

Inspect the fixed repository and original task. Produce a complete implementation
spec that an engineer could implement without guessing about material behavior.
Explain the relevant current behavior, intended behavior, scope, affected code,
proposed changes, compatibility and edge cases, and verification/acceptance tests.
Ground file/symbol references in the repository. Resolve necessary design choices;
do not invent requirements or claim tests have already run. Do not implement code.

Return ONLY the Markdown spec, beginning with a level-one `# ` title. Include
substantive body text, no conversational preamble or postscript, and no enclosing
code fence. Code snippets inside the document are allowed. All source files are
read-only; the benchmark runner will save your final reply as the artifact.

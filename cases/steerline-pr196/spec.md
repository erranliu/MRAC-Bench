# Spec TUI与中心实现解耦

任务 ID：72；任务名称：TUI与中心实现解耦；目标：`CORE-IMPLEMENTATION-DECOUPLING`。配套 [Plan](core-decoupling-11-tui.plan.md)。硬前置：#71 [产品客户端适配层与CLI接入](core-decoupling-10-client.spec.md)整体交付；一个实现 PR。

## 目标与范围

遵守[后续维护共同约束](core-maintenance-constraints.md)。让 console 的 model、默认源、配置选择、决策及渲染只消费 #71 的产品纯契约和小接口，移除对中心 Config/Store/Runtime 实现、开库/连接探测及控制默认实现的依赖。导航、输入、选择、锚点、折叠/滚动和偏好仍由 TUI 拥有。

不 redesign UI、不加入新动作、HTTP/SSE、WinUI 或第二份查询/资格规则。已有渲染拆分继续复用；CLI 已由 #71 接通，不能在本项另建客户端。

## 必须交付

1. ProjectRef/ProjectSnapshot、QuerySource、ControlClient、DecisionCommandClient 和模型字段改用 #71 公共纯值/接口。全体 console 生产/测试源码不导入 steerline 根包、SQL/存储实现、具体平台、默认客户端 adapter 或 steerlineapp；引用不经隐藏别名重新引入中心。外层组装创建 adapter 并注入 console，不能由 UI 构造默认后台。
2. 文件/数据库/配置/项目身份/进程探测及控制/答案提交默认实现唯一归 #71 adapter。删除暂存薄映射和原默认 I/O，模型/渲染只格式化产品事实。方案列表消费非秘密描述与固定身份/支持原因，不在 UI 编译权限或解释实现配置封套。
3. 按钮与快捷键使用服务端资格/原因和精确对象/版本，中心提交时再次校验。UI 的可点击状态不是授权，视图旧数据或身份切换不能发到其他项目/代次。请求 ID 在发送前保留，错误继续查原回执，待核实不显示已成功或生成新 ID 重试。
4. 保留同仓不同配置的偏好隔离、选中任务/会话归属、游标/正文版本、Unicode/字节预算、阅读锚点、待决策内容及原请求查看行为。退出 TUI 只关闭客户端/观察资源，不停止服务/worker。
5. UI 单元测试使用中性产品客户端 fake，验证导航和展示；实际默认 adapter 接线通过应用外层集成保留。迁移测试不能为了移走 import 删除产品断言或导出任意中心写入口。必要依赖检查接到既有守卫/quick，不放宽 #67 根包隔离。

## 并行与最终交付

可与 #69/#70 并行，不改 Store/写端口/领域记录，既有共享 DTO 保持。仅在应用 console 构造段和守卫/测试入口集中集成；不以存储先搬包作为隐藏硬前置。

交付 CLI/TUI 共用产品接口的最终形态，以及客户端/视图模块说明、依赖和最小入口。若仍有中心消费者，必须本项切换删除，不能留下“后续再清理”的默认路径。

# 主包与执行实现解耦共同约束

适用目标：`CORE-IMPLEMENTATION-DECOUPLING`。本文件由六份独立任务 Spec/Plan 引用，不单独启动实现。

## 目标与范围

`internal/steerline/` 直属 Go 包只表达任务、执行业务状态、事务、查询组合和通用执行端口。具体宿主、agent、原生协议、配置编译、资源操作及会话来源由实现包拥有；内置实现的选择和构造由主包之外的应用组装层拥有。

最终直属生产及测试 Go 文件的名称和源码均不得包含大小写不敏感的 `codex`、`orca` 文本。检查包括 import、标识符、字面量、注释及错误文案，不设置例外名单。平台子包和外层集成测试允许包含这些文本。动态目标 ID、用户配置值、平台诊断或历史来源名称可以经过主包作为数据传递，主包不能按其原生含义分支、拼接或解析。

消除文件名不是单独交付目标。禁止改名后继续解释 app-server method、terminal tail、Dispatch、原生问题路由或权限参数。最终主包直接和传递依赖均不能包含具体执行实现或外层组装包。

本系列处理执行、会话采集、宿主交互、执行配置及其组装。现有 workspace/publication、query/sqlite 边界继续复用；不顺带搬迁 SQLite 写实现、重写 Task 状态机、建设插件系统或增加新平台支持。

## 依赖与所有者

下表为最终依赖方向；各阶段必须遵守自身消费者范围，尚未迁移的唯一构造/协调接线按下文交接表保留，不能把阶段性残留宣称为最终达标。

| 层 | 所有者与允许依赖 |
| --- | --- |
| `execution` | 通用身份、请求、事实、操作、问题及消费者所需的小端口；不依赖 contracts、主包、平台、数据库或应用组装层 |
| `contracts` | 业务持久/展示记录及有界实现数据封套，引用 execution；不依赖平台包或组装层 |
| `steerline` | 业务状态计算、单写者、intent/receipt/Decision/TaskDelivery 原子事务、投影及端口调用；只接收显式注入的实现能力 |
| 现有执行实现包 | 原生配置类型、严格 codec、权限/版本解释、绑定、操作、观察及来源解析；使用 execution 和必要 contracts 值，不导入主包或获得业务写者 |
| 外层应用组装 | 位置 `internal/steerlineapp/`；依赖主包和实现包，构造目录/工厂并接通 CLI、服务、查询及控制台入口；不承担业务状态转换 |
| 外层集成测试 | 位置 `internal/steerlineintegration/`；通过真实应用端口验证平台接线，不为测试暴露任意 Service 私有状态或数据库写入口 |

生命周期/问题端口优先使用 execution 的纯值。涉及 ConversationWrite 等 contracts DTO 的来源端口由主包消费者定义，但方法参数/结果只能是 stdlib/execution/contracts 值；实现以 Go 的结构接口满足端口，不导入主包的命名参数或接口类型。端口无需放进 execution 后再反向导入 contracts。

包名可按完整职责调整；依赖方向和所有者不可调整为平台反向调用中心。不将 `func(*Service, *Run, ...)` 换成包含等量可写状态的接口。

## 事实、问题与实现数据

实现只返回经原生身份核验的通用事实、问题正文/选项、观察缺口和原始证据引用。中心判断业务资格、人工授权、轮次用途及交付；接收方来自固定可信路由，不能来自 worker 自报文字。

原生配置、绑定、游标和问题路由使用实现拥有的类型及严格 codec。若需要跨业务记录持久化，封套固定实现 key、codec/schema 版本、用途、摘要和有界载荷。领取前配置属于 Project/Profile 及受理配置版本，不要求尚未分配的 Execution/代次；领取事务把该配置摘要固定到新 Execution。资源绑定、问题路由与读取位置则必须绑定既有 Project/Execution/代次，路由另绑定原问题和 Turn；常用业务事实仍有明确通用字段。载荷只由固定 codec 解码，损坏、未知 key/版本、目标或归属不符必须拒绝。不能用任意 map、没有身份的 raw JSON 或缺乏来源的 opaque blob 隐藏耦合。

配置、绑定、问题路由和 checkpoint 各封套的 UTF-8/字节载荷上限固定为 64 KiB；超过上限拒绝，不截断或只存摘要。正文、原始输出和长期操作历史使用已有独立记录及有界证据引用，不累计进封套；持久化/返回封套必须复制载荷 bytes，codec 不通过共享指针继续修改已受理或已提交值。codec 必须严格校验字段、版本、用途及大小，不包含秘密值；载荷与所属身份/版本共同纳入摘要，摘要不能依靠自报字段替代核验。

中心可以校验封套身份、摘要和版本目录，但不解释 native 字段。codec 不拥有业务提交，也不通过读当前配置补造原绑定。返回值与公开投影均保持深复制和固定所有者。

## 副作用与事务交接

执行分步操作沿用现有 Operation/绑定附件机制：中心保存固定 intent 后调用实现，返回回执/部分绑定后原子提交，再授权下一步。实现不能自行串行执行跨越提交屏障的下一次变更。尤其保留 thread 绑定提交后才发送首轮输入、资源创建回执提交后再派发，以及消息内容与消费事实提交后才 ack 的屏障。

执行实现得到值输入和单个已持久操作，不得到 Store、可写 Service、Runtime 或整份 Domain。纯准备/校验、只读 Observe/Reconcile 与 Execute 分开；不能把读操作变成隐藏安装、登录、创建 worker 或重发输入。复用现有 actor/workerMessages 调度，不新增另一套引擎、状态机或事务提交入口。

异步结果必须携带原 Operation ID/请求摘要、固定目标、Execution/代次及输入绑定摘要；中心通过现有前值核验和 workerCommit 拒绝过期、重复冲突或跨执行结果。实现不能通过返回候选绑定扩权、换端或覆盖当前业务记录。结果提交失败后中心恢复私有候选，平台已发生的动作只按原 intent 对账，不执行下一步。

Operation 的 request ID、摘要、目标、代次和 outcome_unknown 必须保留。未知 start/reply/send/ack 只核对原操作；不得自动换会话、换后端或重发未知输入。观察关闭、宿主退出、远程取消和资源结算分别表达。TaskDelivery 仍由中心按真实 provider 合并事实唯一提交，清理失败不撤销已交付事实。

## 配置、恢复与宿主边界

项目策略与全局执行选择继续分开。应用入口显式注入不可变实现目录，同一目录用于配置受理、Claim、冻结、恢复、查询展示及能力检查；不靠包 init、全局可变注册表或 import 顺序装载默认实现。

发布责任保留项目固定 `worker`/`host_service` 或显式授权 `execution_profile` 的解析语义：选择方案时解析并冻结有效责任及支持矩阵，不能因移动配置所有者改成按 host 隐式推断或取消混合方案。

新执行按受理配置固定实现 key/版本、目标、需求和非秘密引用；原执行按原快照、绑定和 codec 恢复。配置改变或要求缺失不得重写原生存活事实，观察与既有操作对账继续，新输入仍需当前资格。

准备/业务轮、nonce/deadline、工具/收据/结算、DeferredDecision/Feedback 及中心宿主动作的权威保留。重启不自动清除人工门槛，准备晚到成功不自动派发业务；续聊在变更前核验原身份和 incarnation。远端路径按远端值处理，不能使用中心 OS 重写。

remote 缺少权限落实证据时仍在准入前拒绝。协议层模拟和新实现 fake 只证明接线与业务边界，不证明权限、工具可用或双机认证。本系列不承担新增权限证据 producer 或扩展 remote 取消。

## 迁移与最小验收

阶段检查只约束本阶段迁移的生产消费者：#62 统一事件/问题，#63 统一配置和持久 codec，#64 统一生命周期，#65 统一来源/宿主，#66 才移走最终内置组装。#63 的旧生命周期/采集方法可短暂通过唯一 codec 消费实现类型的解码视图，必须列入 #64/#65 的删除清单，不保留旧格式读写或第二份持久字段。共享公共端口禁止原生 DTO，但未迁移方法尚有平台 import 不算最终隔离达标。

每阶段迁移完整消费者并删除对应旧实现；不得交付空接口、无人消费的包或双路生产分派。尚未进入该阶段的唯一实现可以保留，Spec 必须列明交接，不能把当阶段删除推给最终阶段。平台单元测试随所有者迁移，中心事务测试使用中性 fixture，原生集成断言在外层保持。各阶段必须可编译；API 改变造成测试失效时在该阶段处理，不把修编译推到 #67。root 同包测试不能导入依赖 root 的应用组装包。

内部配置/记录格式需要改变时更新受影响版本，旧开发格式明确拒绝并保留现场，不读旧版、不迁移、不双写或回退。当前新格式的恢复与幂等必须成立。历史 Spec 不回写；新要求在本系列中独立固定。

每阶段只运行受影响包的必要用例和一组中心接线，稳定后运行一次最小入口。测试改名/迁包须列旧到新映射并核验实际命中；不用完整故障矩阵或全量测试替代职责审查。实际原生启动或权限映射改变时才补对应最小原生证据。

最终守卫位于主包之外，扫描直属生产/测试源码和文件名、AST import、直接/传递依赖及禁止的反向依赖。源码扫描不受构建标签影响；依赖检查至少覆盖 Windows/Linux 的生产图，源码 import 图还检查其他构建条件的项目内边，不能仅凭当前 OS 的 go list -deps 宣告通过。直接检查和传递遍历均禁止具体执行实现、外层组装/集成包进入根包或通用契约依赖，平台实现禁止反向导入主包；contracts 的业务规则依赖不作为平台实现误报。用外层定义的中性第三实现走同一受理、事件/问题、反馈和恢复端口，证明主包生产代码无需修改；不得绕过强制准入或把 fake 当作认证。

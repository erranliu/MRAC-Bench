# 主包解耦后续维护共同约束

适用目标：`CORE-IMPLEMENTATION-DECOUPLING` 的 #68–#72。每项任务一份独立 Spec、Plan 和一个实现 PR；本文件不单独启动实现，也不改变 #63–#67 的交付要求。

## 基础与范围

#67 [主包隔离守卫与测试归位](core-decoupling-06-boundary.spec.md)整体交付后，#68 清理最终形态下可删除的内容；#68 整体交付后，存储线 #69 → #70 与客户端线 #71 → #72 可以并行。各任务不得提前完整实施或凭接口草案解除硬前置。

保留[主包与执行实现解耦共同约束](core-decoupling-constraints.md)的最终依赖方向、固定身份、配置封套、恢复授权和 intent/receipt 屏障。原 #62–#67 不搬迁写层的范围限制仍适用于那些任务；后续写层迁移仅由 #69/#70 交付。

不增加 HTTP/SSE、原生 UI、规划领域、动态插件、远端权限或新平台支持。现有文件控制协议、命令语义和查询语义继续复用；[本机客户端协议 #45](phase2-local-api.spec.md)的固定硬前置不因本系列新增任务改变。仅规划文件变更不创建中心任务或调整运行时 DAG。

## 状态与事务

业务规则、资格、授权及提交意图由中心用例拥有；SQLite 是唯一持久业务权威，所有业务写入仍通过已有中心用例及事务边界。UI、客户端、执行适配器和组装层不能获得任意数据库或 Domain 修改权限。

写端口按命令受理、worker 转换、任务/DAG/交付及会话提交的真实消费者拆分；请求/结果是类型化纯值，接口不暴露 sql.DB/sql.Tx、原生客户端、可写 Service/Runtime 或任意 SQL/表名。数据库层仍在同一事务重检前值、版本、项目/目标/代次和固定身份，不能只在事务外校验一次。

worker 的业务记录、绑定、操作回执和 checkpoint 保持原子写集合；创建任务与依赖/合同/回执同事务，领取与固定执行记录同事务，交付及后继资格保持现有原子规则。会话事件、正文版本和 source cursor 仍用独立原子事务；heartbeat 仅写服务元数据。失败不发布成功视图、不推进游标、不确认消费。

外部动作仍先提交 intent、再执行，回执提交后才授权下一步；未知结果按原请求对账，不能重派、换会话或静默回退。恢复人工门槛、准备/业务分流和真实唯一 TaskDelivery 不变。

## 依赖与共享修改

| 所有者 | 职责与允许依赖 | 修改归属 |
| --- | --- | --- |

| 存储实现 | 连接、schema、SQL、读事务及写事务执行；不导入中心、应用组装或平台实现 | #70；复用现有 sqlite.Reader，不建立第二条读取路径 |

| 客户端适配层 | 开库/关闭、配置与身份解析、服务连接探测及现有 Query/Command/control 调用 | #71；以 #66 的显式依赖注入接线，不依赖应用组装包 |

| 应用组装与 CLI | 构造唯一实际实现，CLI 解析参数后调用产品接口 | 存储构造段由 #70 修改，客户端/CLI/TUI 构造段由 #71/#72 修改 |

建议写端口纯包为 internal/steerline/persistence，客户端纯包为 internal/steerline/clientcontracts，客户端适配层为 internal/steerlineclient。实施时可调整包名，但上述依赖方向和唯一所有者必须保持。不将中心会回调自身的全能接口或另一份 Runtime 模型伪装成解耦。

#69/#70 拥有写端口 DTO、Store/schema、业务提交接线；#71/#72 拥有客户端 DTO、适配层、CLI/TUI。客户端不得依赖写端口或 SQLite 具体类型，存储线不得改变公共客户端语义。contracts 的既有共享字段形状不在两线并行修改；确需调整时由原类型所有者集中交付，再按该已集成契约推进另一线。组装文件的不同构造段及 quick/守卫入口集中顺序集成；共享修改冲突不是新增业务硬前置，也不能通过双实现暂存解决。

#45、多候选或版本任务若同时修改 Service、公开 DTO、CLI 或组装入口，须约定各自所有者并顺序集成，不自动修改其固定 Spec。

## 删除与最小验证

迁移必须接通真实消费者并删除原实现，不能只交付无人消费的接口或新增长期转发。#68 不接收 #64–#67 应当完成的生产迁移、临时 decoder 删除或测试归位；发现这类缺口先按原任务范围修复，再进入清理。

删除前核对所有 OS/构建标签、产品入口、反射/协议名称、嵌入文件、脚本及外层测试消费者；源码无直接调用不等于运行时无人使用。历史原生证据和旧格式拒绝样本继续保留，不把未认证路径当死代码删除。

各实现任务复用受影响代表用例，稳定后一次既有 quick；检查命名入口实际命中，测试迁包保留旧到新断言映射。只补发现的覆盖缺口，不新增全量测试或完整故障矩阵。保持 #67 守卫有效；迁包时更新所有者和入口，不增加忽略名单。规划阶段只校验身份、依赖、链接和文档一致性，不执行代码测试。

默认不兼容旧开发数据、配置或内部协议；格式必须改变时明确升级版本并拒绝旧格式，保留现场，不迁移、双写、自动重建或回退。结构搬迁本身不要求改变格式。

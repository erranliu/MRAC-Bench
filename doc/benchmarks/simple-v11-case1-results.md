# Simple v11：case 1 历史测试结果

统计快照截至 **2026-10-01**，文档整理于 2026-10-02。范围为本机留存的
`spec-flow-simple-v1` v11、case1 v1 测试记录，共 **39 个终态结果和 3 个暂停结果**：
19 次收敛、8 次未收敛、12 次错误、3 次暂停。取消和仍在执行的 run 不计入。

## 统计口径

- 按模型和 thinking effort 分组，每个 run 计一次。
- “未收敛”指 `NON_CONVERGED`，即审查预算耗尽；预检、执行、解析错误单列。
- “正常流程”只包含 `CONVERGED` 和 `NON_CONVERGED`，错误与暂停不进入正常流程的平均值。
- 耗时来自 runner 的 `usage.wall_time_seconds`，换算为分钟，包含 run 内的准备、审查、评审、修复和闭环执行；不包含事后的报告导出。并行 run 的耗时分别计算。
- **平均修复轮次**为正常流程 run 的 `repair_rounds` 算术平均，保留两位小数。
  `repair_rounds` 计已启动的修复调用，包括修复重试；它不是修复项数量，也不是成功保存的版本数。
- 耗时平均值和范围保留一位小数；范围为同一统计集合的最短至最长耗时。

## 结果解释与限制

- GPT-6 Luna / medium 的四轮都沿用原始 Spec，共报告 6 项发现，评审接受 0 项。
  快速收敛表示满足流程的连续 clean 条件；Spec 质量仍需独立检查。
- GPT-5.6 Luna / high 的三个暂停 run 均触发连续六轮 freeze 审查仍有接受的 P0–P2 修复项的暂停条件。
  暂停没有计为收敛、预算耗尽的未收敛或执行错误。
- GPT-5.6 Luna / high 的错误包括一次执行策略错误和两次读取预检失败；
  GPT-5.6 Terra / high 的四次错误均为读取预检失败。
- GPT-6 Luna / high 的错误包括一次执行策略错误和一次读取预检失败。
- GPT-6.1 Sol / high 的三次错误包括一次 `audit_id` 一致性校验引起的 `PARSE_ERROR`，
  以及两次 Windows sandbox 初始化失败。后两次的原始结果代码为 `REPAIR_INVALID`，
  原因是文件访问失败后候选 Spec 未变化；原始状态在数据中保留。
- 历史运行使用过 Codex CLI 0.156.1 和 0.159.2，Windows sandbox 包括 `elevated` 与
  `unelevated`，并发设置也有变化。比较模型时需考虑这些运行条件差异。

## 数据与复算

[随文数据](simple-v11-case1-results.json)包含 42 个 run 的 batch/run ID、模型、effort、
原始结果、耗时、审查次数、修复调用次数、CLI 版本和 sandbox 模式，可据此复算表格。
数据不包含本机绝对路径或认证信息。

例如 GPT-6 Luna / high 的正常流程共有 9 个 run，修复调用次数合计 26：
`26 / 9 = 2.89`。GPT-6.1 Sol / high 对应为 `17 / 7 = 2.43`。

该文件是历史统计快照；后续新增测试应更新数据并重新计算，避免将新结果直接追加到旧平均值。

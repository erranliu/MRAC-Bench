# Simple v13/v14：case 1 错误修复后的测试统计

统计日期：**2026-10-02**。协议为 `spec-flow-simple-v1`，case1 v1。
本表包含错误修复后的 **10 次完整流程测试**，两个模型各 5 次，thinking effort 均为 high。

实际协议版本不能统一改称 v12：v12 的 10 次诊断调用仍受到 MCP 传输错误影响；
修复该问题后使用 v13 完成 9 次完整流程，随后 v14 调整原始 Spec 的正文展示，完成 1 次。
当前可执行协议版本为 14。本文件以实际测试版本登记，避免与诊断结果混淆。

## 统计口径

- 结果统一为收敛、未收敛、错误。原始 PAUSED 归为未收敛；提前暂停和预算耗尽只记作停止原因。
- 正常流程包括收敛与未收敛，含提前暂停。耗时均值与平均修复轮次使用这个集合。
- 耗时使用 runner 的 wall_time_seconds，包含准备、审计、评审、修复和闭环，不含报告导出。
- 修复轮次为已启动的修复调用数，包括原流程中的修复重试。
- 10 次诊断调用及 3 个启动前取消任务不进入修复后统计；启动的诊断调用已计入 20 次预算。

## 修复内容与解释范围

- 修正 Windows 默认 GBK 与 MCP UTF-8 传输不匹配的问题；原始失败响应可复现，
  修复后中文路径及中文/emoji 内容通过离线往返验证。
- 使用 unelevated Windows sandbox；audit ID 由控制器绑定，预检使用单行默认采样，
  数量参数交由脚本缩到输出上限，原始 Spec 以正文展示；复制、保存、diff 继续由 runner 承担。
- 保留阶段顺序、核心审计标准、8 次审计预算、两次连续 clean 与六轮暂停规则。
- 10 个完整样本的终态错误为零，只说明这批验证未复现错误。v11 包含不同 CLI / sandbox
  条件，运行并发和缓存也有差异；这些是历史对照，不是只改变一个变量的受控实验。
- v14 仅有一个 5.6 Luna 样本；它正常结束为未收敛，不能据此断言正文展示保证避免提前暂停。
- 最终脚本中的单文件结果上限截断标记边界另以离线回归验证，未追加模型调用。
